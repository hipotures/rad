* Default (no --mmap-experts, no resident flags): ArenaExpertSource loads every expert's native GGUF role spans into one allocated host arena. No experts.bin is required. CPU fallback reads this arena; GPU cache fills, DMA misses and adaptive swaps use its RAM bytes. Linux registers the whole arena by default. Runtime verified: T2-auto loads71.73GiB into a fully registered arena, starts both GPUs and completes8K smoke plus3×actual63400-token requests.
* --mmap-experts: FileExpertSource maps all native GGUF shards and assembles expert blobs from checked gate/up/down spans. Bytes are file-backed through the OS page cache. Logical file fetches are not proof of physical SSD reads, particularly on this VM's virtiofs mount.
* --resident-budget-gib: enables mmap plus resident_cpu_experts and pinning, copies the hottest GPU-cache complement into RAM. GPU-cached experts are not duplicated in that complement. Prefill/refill may fetch native GGUF despite zero decode fetches. Guard explicitly refuses both layer split and remote caches; these combinations are UNSUPPORTED_BY_CURRENT_UPSTREAM.
* Layer split: each GPU owns a contiguous layer range and expert cache of those layers. Last stage also owns head/MTP. Host arena exists once; CPU pool computes misses, while a configured fraction can use GPU over PCIe from pinned host memory. One interstage handoff per verify window. GPU hits plus RAM/DMA fallback are distinct compute tiers, so "CPU misses" does not mean every miss executes on CPU.
* Helper cache: GPU0 owns dense/KV/MTP and primary cache; GPU1 owns separate expert pairs, chosen by stripe or whole-layer placement. The remaining misses use host fallback. Every active layer waits for remote results, returned through pinned host staging. CLI accepts a numeric slot count; no remote `auto` is supported. Capacity will be derived from actual free VRAM and layout max_blob, with documented >=512 MiB reserve and extra scratch allowance.
* T1 and T5 are the same default full-arena source, with T5 applied to the multi-GPU T2/T3/T4 configurations. They will not be counted as separate duplicate experiments.
* KV k8v4 explicitly rejects --kv-resident. Conversation parking rejects layer split; ordinary prompt checkpoints support split. Native packs require spec >=2 for the serve/prefill path: non-MTP viability must be checked against guards, not bypassed.

Counters will distinguish startup/prefill/refill versus per-request decode expert tiers. PLE is separate. Physical host SSD traffic and PCIe hardware counters may not be visible to the guest; unavailable fields stay null, not zero.
