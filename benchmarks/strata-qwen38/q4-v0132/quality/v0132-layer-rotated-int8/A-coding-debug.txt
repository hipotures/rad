### Bug Analysis

The provided function has two main issues:

1.  **Input Mutation**: The line `intervals.sort()` sorts the input list in-place. This violates the requirement that "the input must not be mutated."
2.  **Incorrect Merging Logic**: The line `result[-1][1] = end` blindly replaces the end of the last interval with the current `end`. This fails when the current interval is **nested** inside the last interval (e.g., merging `[1, 10]` and `[2, 5]`). In this case, the end should remain `10`, not become `5`. The correct logic is to take the **maximum** of the current end and the last interval's end.

### Corrected Code

```python
def merge_intervals(intervals):
    # Create a sorted copy to avoid mutating the original input
    sorted_intervals = sorted(intervals)
    
    result = []
    for start, end in sorted_intervals:
        if result and start <= result[-1][1]:
            # Merge by taking the maximum end to handle nested intervals
            result[-1][1] = max(result[-1][1], end)
        else:
            result.append([start, end])
    return result
```

### Edge-Case Examples

#### 1. Nested Intervals
**Input:** `[[1, 10], [2, 5]]`  
**Expected Output:** `[[1, 10]]`  
**Explanation:** The interval `[2, 5]` is completely inside `[1, 10]`. The buggy code would incorrectly set the end to `5`, resulting in `[[1, 5]]`. The corrected code uses `max(10, 5)` to preserve the larger end.

#### 2. Touching Intervals
**Input:** `[[1, 3], [3, 5]]`  
**Expected Output:** `[[1, 5]]`  
**Explanation:** The intervals touch at point `3`. Since `start (3) <= result[-1][1] (3)`, they should be merged. The corrected code correctly merges them into `[1, 5]`.
