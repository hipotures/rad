### Bug Analysis

The provided function has two main issues:

1.  **Input Mutation**: The line `intervals.sort()` sorts the input list in-place. This violates the requirement that "the input must not be mutated."
2.  **Incorrect Merging Logic**: The line `result[-1][1] = end` blindly replaces the end of the last interval with the current `end`. This is incorrect when the current interval is **nested** inside the last interval (i.e., `end < result[-1][1]`). In such cases, the end of the merged interval should remain the maximum of the two ends, not just the current `end`.

**Example of Failure:**
Input: `[[1, 10], [2, 5]]`
- Sorted: `[[1, 10], [2, 5]]`
- First iteration: `result = [[1, 10]]`
- Second iteration: `start=2`, `end=5`. `2 <= 10` is True.
- Bug: `result[-1][1] = 5` → `result = [[1, 5]]`
- Correct Output should be `[[1, 10]]` because `[2, 5]` is nested within `[1, 10]`.

### Corrected Code

```python
def merge_intervals(intervals):
    # Create a sorted copy to avoid mutating the original input
    sorted_intervals = sorted(intervals)
    result = []
    
    for start, end in sorted_intervals:
        if result and start <= result[-1][1]:
            # Merge by taking the maximum end value to handle nested intervals
            result[-1][1] = max(result[-1][1], end)
        else:
            result.append([start, end])
            
    return result
```

### Edge-Case Examples

#### Edge Case 1: Nested Intervals

**Explanation:** All intervals are nested within `[1, 10]`. The merged result should remain `[1, 10]`.

#### Edge Case 2: Touching Intervals
**Input:** `[[1, 2], [2, 3], [4, 5]]`  
**Explanation:** `[1, 2]` and `[2, 3]` touch at point 2. They should be merged into `[1, 3]`. `[4, 5]` is separate.
