## Repaired real-logarithm cutoff

The historical v1 source comments used `K>=8L+40` with
`L=log2(b_input)`. For real L and p=6b, the safe elementary ceiling is
`ceil(log2 p)<=L+4`, so the actual required bound is `K>=8L+48`.
This is a wording defect in the displayed comparison, not a failure of
the historical cutoff, whose exact integer slack is enormous.

The fresh adapter explicitly checks

```
k=ceil(1/(epsilon*c)), L0=64*k^2+1,
2^floor(L0/k) > 32*L0+192.
```

For real L>=L0, the ratio `2^(L/k)/(32L+192)` increases: its logarithmic
derivative is greater than `1/(2k)-1/L`, which is positive since L0>2k
and log(2)>1/2. The existing floor bounds then give

```
K >= b^(epsilon*c)/4 >= 8L+48
  >= 8*ceil(log2 p)+16 = G+4*ceil(log2 p)+10.
```

## Limiting mechanism and scope

For primitive savings a=1-tau, b=1-sigma, the declared compact family has
the scoped ceiling

```
min(a/(2+a), a*b/(4*a+b), b/5).
```

At h28 the certified complex saving is about3.7940e-8, while the promoted
bit saving is about3.1113e-9. The prefix branch a/(2+a) is strictly
smallest. Removing only the CRT margin cannot improve that ceiling: it
already follows from compact internal g3, bit layout movement g2 and
prefix g1. A stronger bit circuit can increase a, whereas further complex
improvement gives only guard/cutoff headroom until an active branch changes.
These are exact conclusions for the declared interfaces, not limitations
on all possible multiplication algorithms.
