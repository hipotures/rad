# Exact early exclusion of duplicate future-output complements

The complete original h25 graph and actual maximum matching were rebuilt.
For all46,375 nonsource regions, both the future-OUTPUT and reversed-OUTPUT
heuristics select exactly the same ordered full regional row matrix as the
standard-unit completion. This is an exact full-graph discriminator, not a
sample or a guessed duplicate based on equal R. The [receipt](results/h25.json)
binds executed code/helper/producer hashes and all counts.

At a fixed original region order, matching and acquire policy, identical
regional matrices produce the same deterministic XOR and reclamation word.
The ignored index on a `retire` label has no consumer; requested and carry
labels remain identical. Thus the two future-OUTPUT cases add no mathematical
information to the accepted guarded-live h25 compiler. A changed order or
matching requires its own discriminator and is outside this result.

The expensive ongoing future-consumer SUM case was allowed to continue while
this discriminator ran. The user then requested graceful shutdown: that SUM
case was still incomplete and was cancelled; its proven-duplicate successors
were never launched. No existing high-value computation was stopped merely
to reach a utilization target. The prepared sparse-first continuation was
also not launched after shutdown.

hash-pinned public source, h25 and a fresh output path. The result does not
replace complete word/profile checks for any changed regional matrix. New
