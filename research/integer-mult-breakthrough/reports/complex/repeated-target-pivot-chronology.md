# One dirty target can serve three successive cap cuts

The `j3/j4` local five-cube packets can use one target as the pivot for all
three actual-row channels. The first cut uses the identity frame; the later
cuts use the identical actual rank-five cap representative. No target frame
descends. Every original dirty target value, retained ancestor response and
parked source kernel bank is preserved. This is a changed local chronology,
not a complete global side supplier or exponent result.

For one active channel `a`, let `kappa_a=D[c,a]` be its nonzero coefficient
at the chosen target `c`. Set `w_a[t]=D[t,a]/kappa_a` for `t != c` and
`w_a[c]=0`. The chronological three steps are:

1. Subtract `w_a[t]*y_c` from each nonpivot destination.
2. Add `kappa_a*g_a` only to `y_c`.
3. Add `w_a[t]*y_c` back to each nonpivot destination.

The resulting change is `D[:,a]*g_a`. This calculation holds for the current
arbitrary value of `y_c`, including every channel accumulated before this
cut. Therefore the same pivot can be used at the next cut. A nonpivot
correction made between these two cuts survives unchanged. A pivot
correction inside its cut would be broadcast and is rejected by the test.
The pre/write/post sequence is completed for each channel before starting
the next; merging all pre-cuts and all post-cuts is not justified.

Both local decoders have a missing-row target with all three coefficients
equal to `-1`. The source chooses target index 12 at `j3` and 6 at `j4`.
