# Persistent runtime safety and mechanism

The modified worktrees start from frozen `6f32ec070f23ced9f50e704d854d775da52591ab`. Source diffs/build commands are preserved per attempt. No clean/control checkout, model, or normal user launcher is modified.

Enabled only with explicit `STRATA_LAB_PERSISTENT=1`, exactly two sequential stages, K25, serial one-group spec4, full immutable resident RAM arena, no helper/peer/resident-complement/mmap/elastic/batch, suffix/reuse OFF. OFF retains upstream per-layer adaptation. A new OFF binary is checked against original P1 outputs/MTP/routing to detect an unrelated integration change.

Prediction projects the existing local target-layer BF16 gate on the fresh GPU normalized activation at origins5/12/25/32/38, targets13/20/33/40/46. The native actual router has already saved true IDs/weights before scratch logits are reused. Prediction writes separate mapped IDs/confidence with its own fence/doorbell; host consumes after the original expert-dispatch ring fence. No CPU copy of activations and no duplicate gate weights. Explicit allocation320GPUbytes and1664mappedhostbytes perdevice; capacities remain exact frozen physical slots. No external CUDA timing events in the speed candidate.

Recent true demand and prediction heat are separate arrays. Prediction can alter admission only; it cannot alter router-selected experts or combine/reduce mathematics. All speculative branches use their true experts, including later-rejected branches. Counting speculative branch demand follows the original usage convention; it is not a claim that every admitted branch expert was ultimately emitted.

Copies issue in the existing adaptive thread AFTER `Verifier::run` returns from the completed verify stages. No expert readers remain in that window. Do not use host CUDA API calls inside a spinning verify graph: existing upstream issue31 documents driver-lock deadlock. Adapt overlaps commit and draft. The adapt thread is joined before the next verify iteration. Existing pending-copy events are waited for before publication, all participating stages complete, then the host identity is published and residency tables are uploaded to both GPUs. v2 additionally rejects failed CUDA completion rather than publishing. There is no speculative early publication and no temporary restore.

Victim selection is same-device with exact physical slot fit; cross-layer only within that device's ownership. Per-GPU budgets are never combined. Victim slots are disjoint, incoming experts are unique, pending slots disappear from resident candidate selection, and the next selection waits until prior reservations are published. Minimum resident age and recent-use protection prevent immediate churn. Slots and weights do not grow. Immutable arena bytes remain canonical; clean eviction does not copy weights back to RAM.

Meaningful tests: shared C++ selector budget/fit/recency/age/uniqueness/reservation tests; shared runtime identity/repeated-use/victim accounting tests; existing native expert/router/prefill suites; actual greedy10prompt battery with finite-head diagnostics; full4K live32/128 diagnostic weight readback from CURRENT expert slots against canonical RAM. Readback is after decode timing and excluded from headline speed. These do not prove every possible interleaving, every output position, or general model quality. No synchronization primitive in the CPU pool is changed.

Statistics use bounded per-expert counters and per-admission records. No synchronous per-token log/activation copy; detail CSV is written only after the decode timer. Exact first-use timestamps are captured once per admission. Selector cost and publication waits are counted separately. Final speed uses normal lightweight1Hz RSS/CPU/GPU/RAM/I/O telemetry, not PSS polling or NaN checks.
