# Fixed-work contract v2

The logical clock is (request, prefill/decode phase, main/MTP role, verifier-window index, layer, absolute token position, speculative lane). Main routed event index is window*48+layer. A main event retains the complete T-by-10 demand batch, weights, and dependency on the preceding main layer. T is 1..4. MTP draft/catchup computation, confidence early stopping, acceptance, commit/rollback, emitted prefix and positions remain frozen. Native dense, attention, PLE, GDN, routing, expert, shared-expert, final-head and MTP kernels execute. Overrides occur only after actual router/top-k/head computation and before their discrete results feed later control flow.

Version 2 additionally freezes the 12 main QSA sparse-attention selections (up to 4*2051 token indices per layer/window), after computing native block scores/top-k and before KV resolution. MTP attention uses deterministic sliding-window identity selections, whose input positions/shapes are frozen. KV page residency/service can vary with scheduling, but the attention selections, masks, logical append/commit/rollback and amount of mathematical work cannot. The tape also records and checks the initial cumulative native adaptation window count (25 after the fixed 4096-input/64-output warmup). This matters because the serve loop's counter persists between requests.

All 48 main routed layers and actual full MTP routed invocations are captured. No hidden activations are substituted; eight selected activation components per routed call are observed for finite-value/numerical checks. Original and oracle arithmetic can differ under CPU/GPU execution. Forced token equality is not evidence of model correctness.

Prefill is computed naturally with exact input IDs in both arms, without route overrides. At decode boundary the initial expert resident table including physical slot IDs and native usage/heat must match the tape bitwise. Oracle resources are created before cache auto-sizing in both arms. Oracle withdraws five existing class-compatible slots only after the timed decode boundary; no untimed promotion or preload.

Tape records and observations use buffered memory. Data is loaded into RAM before timed execution in both replay arms. SHA256 work identity excludes elapsed times and execution service; it includes tokens, windows, route coefficients, shapes and QSA selection/dependency data. Initial-state identity is checked separately. Native main/MTP/attention computation is not skipped by either arm.

Version-1 pilots are retained as scoped mechanistic measurements. They did not freeze sparse-attention selections, so they are excluded from final full-work headline A/B.

## Masks, dependency graph and logical batch shapes

Absolute position p and verifier lane j define the causal attention mask for position p+j. Main GDN/PLE state advances through the same prefix and rejected-branch rollback schedule. The first input is the recorded last prompt token; subsequent input IDs, draft chain, acceptance prefix and next-window position are validated. The immutable dependency topology is embedding/PLE -> main layers0..47 -> verifier head/commit -> actual MTP catchup/draft steps -> next window, retaining the existing layer-split handoffs and per-layer GPU/CPU concurrency. The complete T*10 routed batch is one milestone; individual experts are never artificially serialized.

The tape freezes logical per-expert token assignments and T (1..4) shapes. Physical service grouping necessarily differs when demand moves from CPU to resident GPU; this is the treatment, not an omitted workload. Native planning, grouping and expert/attention computation remain executed. GPU and CPU activation quantization differ in the existing Q4 runtime (CPU Q8_K vs GPU Q8_1), so natural arithmetic/router/head divergence is expected and separately retained. Forced schedule/output equality is not a quality or bitwise-math claim.

The v3 initial-state sidecar strictly verifies expert capacity/slot/heat/adaptation phase plus meaningful numerical GDN/PLE/KV/MTP state. It is separate from the work hash, which intentionally excludes service location and wall-clock timestamps. Both arms load identical tape/index RAM before execution, compute normal prefill from exact input IDs, perform the same state attestation, then enter timed decode. No oracle copy occurs before this boundary.
