# Initial state attestation — protocol v3

Version2's exact expert slots/heat and numerical current trajectory were insufficient to attest streamed-KV service state. Version3 additionally records/checks a separate initial-state sidecar at the boundary after normal prefill and before timed decode. This is a contract repair, not scheduler tuning. Version2 scoped pilots and tapes remain immutable. Final headline points use the strengthened common binary.

Checked state includes main GDN recurrence/conv arrays, HC residual, PLE token/history, all QSA pooled-indexer/tail/dead data, KV page tables, streamed slot identities/reference/epoch/control, canonical authoritative host KV written prefix, and MTP ring state. Fully resident/ring numerical pools are checked. Streamed VRAM pools are redundant canonical-host copies whose identity maps are checked; authoritative host payload is checked, with native KV mover correctness covered by tests. Unwritten host tail cells and unused old MTP host prefix are excluded because kernels cannot read them in this zero-reuse fixed workload. No bytes are substituted, no KV/expert caches reset, no oracle weights copied during setup.

A component mismatch fails the attempt with named expected/actual hashes. Initial-state read/hash cost is measured as setup_ms and is included in total request-comparable wall. It is excluded from native prefill/decode throughput intervals, whose boundaries remain unchanged. This extra audit is experimental and not installed in normal serving. Hashing large canonical KV data can materially increase setup time; report it explicitly rather than hiding it.

Exact model/native format, auxiliary, main/draft identities and immutable weights are separately verified. Replay token/route/coefficients/QSA work fingerprint excludes initial service state; initial state has its own strict identity checks. A fixed-work comparison does not claim bitwise arithmetic after changing CPU/GPU expert execution.
