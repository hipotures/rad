# Predeclared full-scope feasible oracle prototype

This prototype keeps one already-allocated physical spare per expert byte class present on each device: three on GPU0 and two on GPU1. Those five slots are withdrawn only after the timed decode boundary. All 48 main layers and all three native Q4 classes are eligible. MTP experts remain in their original fully resident arena. No extra expert VRAM, cross-device execution, model gate or combined memory pool is introduced.

A real dedicated CUDA worker per device/class stages immutable RAM bytes into a pinned buffer, copies them on a nonblocking stream, records completion, and publishes residency metadata only after completion. Every copy is logged with logical issue/target/publication IDs and observed monotonic staging/copy times. Missing readiness preserves the recorded demand on the original safe CPU/mapped path. No recorded wall-time triggers are used.

Within oracle scope there is one admission authority: oracle owns all main decode exchanges. Native adaptation is unchanged in replay-current. Oracle retains the native heat-count update/decay but replaces native exchanges only while the selected replay request is active. Native warmup and prefill are unchanged in both arms. This is a policy substitution, not removal of the replay baseline's adaptation. Both policies charge their own copies and planning.

Victims must have the same layer/class and must not belong to any recorded current-window routed batch for that layer. This conservative protection also covers future lanes of the current window; the graph's sequential group1 dependency and prior-window completion prevent readers of other experts. No eviction occurs while copying into the spare. A completed copy may publish at a legal host-plan boundary; the victim's old same-class slot then becomes the spare. All host/device mappings are updated together before the planner is released.

Full-future uses the entire recorded future for victim next-use and repeated-use utility. The online issue frontier remains bounded to feasible near-future events and rolling measured copy/observed event costs; this is a heuristic using full knowledge, not an optimal bound. The optional short arm restricts incoming utility and victim future queries to H future main routed invocations. Beyond H is unknown; recent native heat is the conservative fallback. One event contains a whole T×10 demand batch, not individual experts, tokens or windows.

Initial strategies: (1) deadline/next-use prefetch with conservative victim protection; (2) reuse-amortized persistent admission if the first has repairable churn/traffic problems. No dense parameter sweep. End-of-tape unknown reuse is explicitly censored; pending bytes, spare withdrawal and mandatory restoration are included in comparable request wall time. Finite end knowledge remains a disclosed privilege.
