# Historical workload audit

The audit opened 124 distinct payload files from the seven requested manifest lineages, including the completed conditional-admission campaign, and their actual request builders. Exact system/user messages, saved token-array counts/hashes, source boundaries, identifier locations, repeated long-line counts, source-heading duplicates and immutable payload snapshots are in workload-inventory.json. prompt-catalog.md quotes the actual instructions and source prefixes. No payload had to be reconstructed solely from token IDs: request messages are present; saved IDs were read and counted rather than assuming a report described them.

## What the requests contain

- Original repository-maintenance requests concatenate Strata repository files in sorted order, wrapped in `### filename` fences. The system says "coding agent" and some wrappers say "coding-agent history", but these are source snapshots with no actual tool execution or interactive transcript. The final task demands 40 sections, unified diffs and tests, artificially extending the response. A hex run ID is in the system message. The warmup is a 4096-token character-truncated CMake source excerpt with a 64-token output cap; it is infrastructure, not a natural independent task.
- The original upstream `build_text` cycles its file list when a requested character length exceeds the corpus. That capability is not proof that any particular saved prompt repeats. The inventory records actual duplicate headings/long lines for each inspected payload, including extended 256K material. 32K/128K repository run1 and warmup have no repeated source headings. They are nested excerpts from one repository, not independent tasks. Later lab builders preserve the nonce and final task while taking the largest complete-line prefix inside the context/output reserve; an individual file may still be incomplete.
- E026 code concatenates real HEG repository documentation, SQL migrations and Python modules. E026 math concatenates CPython rational/statistical/decimal/random modules and NumPy polynomial implementations. E026 prose concatenates RFC 9110 then RFC 9111. Full selected source snapshots are preserved. The builder uses one complete-line prefix of that concatenation, with no filler or cycling. The 32K/128K and three nonce variants within a family are one shared source lineage, not six independent tasks. Output demands for 20 worked numerical examples or 30 failure/incident cases make these sustained-output stress tasks. The HTTP source includes authentic RFC headers/legal boilerplate, not invented padding.
- Issue921 reuses those E026 sources and three nonce variants, with a fourth repetition of variant1. Its Q4-v2 appends a 110-token instruction requesting at least 18000 words and 60 worked cases; this is explicitly artificial output elongation. It is retained in historical evidence and excluded from the new natural corpus. IQ3 payloads did not receive it. Issue921 uses the newer 0.1.40-generation engine and supplies aggregate/timing evidence, not full routing tapes for this Phase0 control.
- Earlier short dev/cal/hold requests contain only a brief authored instruction: graph implementation, Markov hitting times, fictional water incident handbook, SQLite ledger, interpolation and 80-case datetime JSON. They have roughly 59–72 Q4 input tokens, not 32K occupancy. They were used in prior predictor work; original holdout names do not make them pristine now.
- Conditional-admission adds four distinct CPython module excerpts (asyncio queue, thread executor, logging handlers, zipfile), four fully specified authored applied mathematical problems and four realistic but fictional structured/prose packets. Code excerpts are the first 26000 characters, potentially ending mid-line; the zipfile request ends in an incomplete comment. Their task sources and historical roles are saved in datasets/tasks.json. The archive importer is a source-grounded offline task, not a executed archive extraction. The fictional incident packets remain useful labelled synthetic examples, not real public logs.

## Provenance, independence and reuse

Strata source is MIT, HEG declares CC0-1.0, CPython modules use PSF terms, NumPy polynomial sources use BSD terms, and RFC sources carry IETF Trust Legal Provisions. Payloads generally do not retain an exact upstream document revision; source snapshots and original text hashes are the authoritative historical identity. Do not invent a revision from a newer checkout. All historical source/nonce/context variants stay with their source group. Common collection membership is recorded separately from document/task identity.

Existing Q4 live-oracle capture schema2 records full main/MTP routing, coefficients, speculative rejected lanes, sparse-attention selections, initial residency/heat and initial-state sidecars. Natural-record mode computes all expert contributions and native generation. With oracle mode off, its observation hooks record native cache events without future-informed changes. The original binary/source and capture derivative are separately verified; capture timing is not clean-baseline timing. Existing full tapes are reused by immutable path/hash where compatible, rather than recaptured just to create files. Prior natural-vs-recording validation is development-only and short, so its overhead cannot be transferred as a universal correction.

## New-corpus eligibility

No random padding, repeated paragraphs, repeated nonce variants, 40-section/book-length wrapper or historical warmup enters the natural core. New code tasks use coherent source excerpts; math keeps substantive fully specified problems (including short prompts); text uses genuine standards, with subtask/language tags; structured work uses a real build log, a real grammar specification and a real SQL DDL. Credential/private-key pattern scans run before model use; no prompts/logs are uploaded. Every core task is a single offline request with tool_execution=false.

Reserved evaluation excludes future fitting by default. Previously exposed reserved tasks are explicitly marked exposed rather than advertised as pristine. Infrastructure recording is allowed for them; their routing is not used to choose features, policies or families. Domain-specific usefulness is preserved, with no oracle-gain selection and no policy tested in Phase0.
